## 1. เหตุใดการเปิด `templates/index.html` ตรง ๆ จึงไม่เท่ากับการรัน Flask?

เพราะไฟล์นั้นเป็น **template** ไม่ใช่หน้าเว็บสำเร็จรูป ในไฟล์มี placeholder ของ Jinja
เช่น `{{ form.vcc }}`, `{{ "%.3f"|format(result.vb) }}` และ `{{ url_for('static', ...) }}`
ถ้าเปิดด้วย `file://` จะไม่มีโปรแกรมใดแทนค่าเหล่านี้ให้ ผลคือเห็นเครื่องหมายปีกกา
หรือช่องว่างแทนตัวเลขจริง และ `<form action="/calculate">` จะชี้ไปยัง path ที่ไม่มี
เซิร์ฟเวอร์รองรับ กด Calculate แล้วจึงไม่มีอะไรเกิดขึ้น

เมื่อรันผ่าน Flask ตัว server จะรับ request, เรียกฟังก์ชัน Python, แล้วส่ง HTML ที่
**แทนค่าครบแล้ว** กลับมาให้เบราว์เซอร์ นี่คือความต่างระหว่าง "ไฟล์ข้อความ" กับ
"โปรแกรมที่ทำงานอยู่": ตัวเลขบนหน้าจอมาจากการคำนวณใน `dc_bias.py` ไม่ได้ถูกพิมพ์ไว้ในไฟล์

## 2. ฟอร์มส่งข้อมูลไป Python อย่างไร?

1. ผู้ใช้กรอกค่าแล้วกดปุ่ม `Calculate DC Bias` ซึ่งเป็น `<button type="submit">`
   ของฟอร์มที่กำหนด `method="post" action="/calculate"`
2. เบราว์เซอร์รวบรวมค่าจาก input ทุกช่อง (attribute `name` เช่น `vcc`, `r1`, `beta`)
   เข้ารหัสเป็น `application/x-www-form-urlencoded` แล้วส่ง HTTP POST ไปที่ `/calculate`
3. Flask จับคู่ path กับฟังก์ชัน `calculate_route()` ใน `app.py`
4. ฟังก์ชันอ่านค่าด้วย `request.form.get(name)` เป็นข้อความ (string) ทั้งหมด
5. `parse_inputs()` แปลงเป็น float, ตรวจค่าว่าง/ไม่ใช่ตัวเลข/nan/inf และค่าที่ต้องมากกว่า 0
6. ถ้าผ่าน `calculate()` จะคำนวณ DC operating point แล้ว `render_template` ส่ง HTML กลับ
   (ถ้าไม่ผ่าน คืน HTTP 400 พร้อมข้อความ error รายช่อง)

จุดสำคัญคือ Python ไม่ได้อ่านไฟล์ HTML ของผู้ใช้ แต่รับ **ค่าที่ผู้ใช้ส่งมาใน request**
แล้วคำนวณสดทุกครั้ง

## 3. แก้สมการใน `dc_bias.py` แล้วต้องแก้ HTML หรือไม่?

**ไม่ต้อง** สำหรับการเปลี่ยนสูตรหรือการเพิ่ม warning เพราะ `templates/index.html`
แสดงเฉพาะค่าที่อยู่ใน `DcBiasResult` (เช่น `result.vb`, `result.region`, `result.warnings`)
ไม่ได้ฝังสมการหรือตัวเลขผลลัพธ์ไว้เลย — นี่คือผลของการแยกชั้น (separation of concerns)

แต่ต้องแก้อีกสองที่:
- `tests/test_dc_bias.py` ถ้าค่าอ้างอิงเปลี่ยน (เช่นเปลี่ยน VCE,sat หรือแก้สมการจนค่าผลต่าง)
- `docs/validation.md` และตารางใน `README.md` ให้ตรงกับฟิสิกส์ใหม่

ต้องแก้ HTML เฉพาะเมื่อ **รูปแบบการแสดงผล** เปลี่ยน เช่น เพิ่มปริมาณใหม่ที่ต้องมีแถวในตาราง
หรือเปลี่ยนหน่วยที่แสดง

## 4. ทำไมผลใน Region ที่แบบจำลองใช้ไม่ได้จึงต้องมี Warning?

เพราะสมการที่ใช้อยู่ (VBE คงที่ 0.7 V, β คงที่, รอยต่อ base-collector ไบอัสย้อน)
**มีเงื่อนไขว่าต้องอยู่ใน Forward Active** เมื่อออกนอกช่วงนั้น ตัวเลขยังคำนวณได้
แต่ความหมายทางฟิสิกส์หายไป:

- **Cutoff** (`VTH ≤ VBE`): สมการให้ IB ติดลบ ซึ่งเป็นไปไม่ได้ในวงจรจริง กระแสจริงเป็นศูนย์
  ถ้าไม่เตือน ผู้ใช้จะเห็นกระแสติดลบแล้วเข้าใจผิด
- **Saturation** (`VCE ≤ 0.20 V`): กระแส collector ถูกจำกัดด้วย RC/RE ไม่ใช่ด้วย β
  สมการ `IC = β·IB` จึงทำนายกระแสสูงเกินจริง (ในเคสทดสอบให้ VC ติดลบ −40 V)
  ค่าที่ควรใช้คือ `IC,max ≈ (VCC − VCE,sat)/(RC + RE)`

การมี warning ทำให้เว็บไม่โกหก: มันบอกว่าผลนี้มาจากแบบจำลองหนึ่ง และแบบจำลองนั้น
ใช้ไม่ได้ในสภาวะที่ผู้ใช้ป้อนเข้ามา ผู้ใช้ต้องเปลี่ยนค่าอุปกรณ์หรือใช้เครื่องมือที่แม่นกว่า
(เช่น SPICE) ก่อนตัดสินใจ — การไม่มี warning จะทำให้ผลที่ผิดดูน่าเชื่อถือ ซึ่งอันตรายกว่า
การไม่มีผลลัพธ์เสียอีก
